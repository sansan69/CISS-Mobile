## 1. Flutter Mobile App — Issues

### CRITICAL

#### C1: QR Flow missing offline queue support
**File:** `lib/features/attendance_qr/qr_attendance_flow.dart:480-540`

The guard attendance screen queues attendance via `offlineQueueProvider` when the network is down. The QR flow does NOT — it just shows a SnackBar with "Failed: ..." and a Retry button. Guards in the field with poor connectivity will lose attendance records.

**Fix:** Add the same offline queue pattern from `guard_attendance_screen.dart:400-418`:
```dart
catch (e) {
  if (e is DioException && (e.type == DioExceptionType.connectionTimeout || ...)) {
    await ref.read(offlineQueueProvider).enqueue(
      path: '/api/attendance/submit', method: 'POST', body: {...payload, 'photoDataUrl': dataUrl},
    );
    // Show "queued for sync" message, proceed to confirmation
  }
}
```

#### C2: QR Flow submit payload missing GPS location fields
**File:** `lib/features/attendance_qr/qr_attendance_flow.dart:510-530`

The guard attendance screen sends rich location data (`locationText`, `locationCoords`, `distanceMeters`, `gpsAccuracyMeters`, `locationAccuracyMeters`, `geofenceRadiusAtTime`). The QR flow sends none of these. The backend may require them or silently ignore them — either way, the attendance record is incomplete vs. the logged-in flow.

**Fix:** Match the payload shape. Capture GPS position before submit:
```dart
Position? pos;
try { pos = await Geolocator.getCurrentPosition(...); } catch (_) {}
// Add to payload:
if (pos != null) {
  'locationCoords': {'lat': pos.latitude, 'lon': pos.longitude, 'accuracyMeters': pos.accuracy},
  'gpsAccuracyMeters': pos.accuracy,
  'locationAccuracyMeters': pos.accuracy,
  'distanceMeters': site.lat != null ? Geolocator.distanceBetween(pos.latitude, pos.longitude, site.lat!, site.lng!) : 0,
  'geofenceRadiusAtTime': site.geofenceRadiusMeters,
}
```

### IMPORTANT

#### I1: QR scanner — no debounce on repeated detections
**File:** `lib/features/attendance_qr/qr_attendance_flow.dart:108-113`

`mobile_scanner` fires `onDetect` rapidly (every frame while a QR is in view). Once `_loading` is set to true, subsequent detections are ignored — but if the API call fails and `_loading` is reset to false, the same QR will trigger another detection cycle. A `_lastScannedAt` timestamp debounce would prevent this.

**Fix:** Add a timestamp guard:
```dart
DateTime? _lastScannedAt;

void _onQrDetected(String rawValue) {
  if (_loading) return;
  if (_lastScannedAt != null && DateTime.now().difference(_lastScannedAt!).inSeconds < 3) return;
  _lastScannedAt = DateTime.now();
  // ... rest
}
```

#### I2: Live location — no stale-data indicator for FO
**File:** `lib/features/field_officer/presentation/screens/field_officer_attendance_screen.dart:438-471`

The `_LiveDot` widget shows green/red based on `isOutOfZone` but doesn't indicate how old the location data is. A guard could have been offline for 2 hours and the FO would still see a green "live" dot.

**Fix:** If `updatedAt` is older than 10 minutes, show the dot as grey/orange with a "stale" tooltip. Add `GuardLocationData.updatedAt` check:
```dart
final isStale = location != null && 
  DateTime.now().difference(location!.updatedAt).inMinutes > 10;
final color = isStale ? Colors.grey : (hasLive ? (location!.isOutOfZone ? Colors.red : green) : fallbackColor);
```

#### I3: Guard detail screen — no loading/error state for map tiles
**File:** `lib/features/field_officer/presentation/screens/field_officer_guard_detail_screen.dart:137-145`

If OSM tile server is unreachable, the map shows a blank grey area with no indication of the error. The guard marker and circles are still visible but there's no geographic context.

**Fix:** Add `errorTileCallback` to `TileLayer` and show a banner when tiles fail:
```dart
TileLayer(
  urlTemplate: 'https://tile.openstreetmap.org/{z}/{x}/{y}.png',
  errorTileCallback: (tile, error, stackTrace) {
    debugPrint('Map tile error: $error');
  },
  // ...
)
```

#### I4: QR Flow — Photo marked optional but guard flow requires it
**File:** `lib/features/attendance_qr/qr_attendance_flow.dart:370-385`

The guard attendance screen REQUIRES a photo (`if (_photoPath == null) { setState(() => _error = 'Please capture a photo...'); return; }`). The QR flow treats it as optional. This creates an inconsistency — same backend endpoint, different validation.

**Fix:** Either make the guard flow also optional (add a "Skip" button) or make the QR flow require it. Match both flows to the backend's actual expectation.

#### I5: `_scannerController` initialization timing
**File:** `lib/features/attendance_qr/qr_attendance_flow.dart:45-47`

`MobileScannerController` is created in `initState`. The `MobileScanner` widget accepts `controller:` — but if the widget builds before `initState` completes (unlikely but possible), the controller might be null. The `MobileScanner` falls back to creating its own internal controller if `controller:` is null.

**Fix:** No crash risk, but verify the controller is used correctly. The current pattern is fine for Flutter's lifecycle.

### MINOR

#### M1: Duplicate `_formatTime` / `_formatDateTime` methods
**File:** `lib/features/attendance_qr/qr_attendance_flow.dart:602-614, 783-793`

Two identical date formatting methods exist — one in the flow class and one in `_ConfirmationCard`. Extract to a shared utility.

#### M2: `LiveLocationService` instantiated inline
**File:** Multiple locations — `LiveLocationService()` is created fresh each call

The service creates a `FirebaseFirestore.instance` getter each time. While Firestore.instance is a singleton and cheap, best practice is to use Riverpod for dependency injection.

**Fix:** Add a provider:
```dart
final liveLocationServiceProvider = Provider<LiveLocationService>((ref) => LiveLocationService());
```

#### M3: QR scanner screen — hardcoded colors in dark environment
**File:** `lib/features/attendance_qr/qr_attendance_flow.dart:90-94`

The scanner overlay uses hardcoded `Colors.white` / `Colors.white70` which work on the dark camera background but don't adapt to theme changes. Low priority since this screen is always dark.

## 2. Next.js Web App — Required Changes

### W1: No Firestore subscription for `guardLocations`
**Files:** `src/app/(app)/dashboard/page.tsx`, `src/app/(app)/attendance-logs/page.tsx`

The web dashboard already uses `onSnapshot` from Firestore for other collections. The `guardLocations` collection needs similar treatment:

**Admin Dashboard (`src/app/(app)/dashboard/page.tsx`):**
- Add a `useEffect` with `onSnapshot` on `collection(db, 'guardLocations').where('status', '==', 'In')`
- Show a "Live Guards" section with count + optional list
- The existing `ClientCoverage` interface already has `checkedInToday` — add `liveOnDuty: number`

**Attendance Logs (`src/app/(app)/attendance-logs/page.tsx`):**
- When viewing a specific guard's attendance, show their live location on a map (Leaflet or Google Maps)
- The attendance record already has `employeeId` — use it to query `guardLocations/{employeeId}`

**Client Dashboard (`src/components/dashboard/client-operations-dashboard.tsx`):**
- Subscribe to `guardLocations` filtered by `clientName`
- Show live guard count and optional map
